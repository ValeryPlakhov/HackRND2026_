# Blueprints Web — практическое руководство

Руководство для веб-версии с группами действий и обучением. Актуально для доработки на базе `fcf2330`, 25 октября 2026 года.

## Первый вход: два пути

При первом открытии выберите:

- **Я впервые здесь** — загрузится учебный интернет-магазин с шестью готовыми тестовыми входами. Тур проведёт через карту, строку действий, метод, порты, исправления и проверку.
- **Я уже работал с редакторами** — сразу откроется стартовая страница. Можно открыть свою папку, готовый пример или создать проект.

В туре есть «Назад», «Дальше» и завершение. Escape завершает тур. Повторный запуск находится в **Помощь → Обучение по интерфейсу**. Если проект уже открыт, обучение использует его и не заменяет другим примером. В таком проекте готовых тестовых входов может не быть.

Встроенная краткая справка доступна кнопкой **Руководство**, а также в группе «Помощь».

## Где что находится

Четыре больших раздела в верхней строке отвечают на разные вопросы:

| Раздел | Когда открывать |
|---|---|
| Обзор | Что за проект, где main, какие методы требуют внимания |
| Метод | Прочитать или изменить конкретную функцию |
| Задачи | Разобрать диагностику, предложение изменения или выделение класса |
| Проверка | Настроить входы и сравнить поведение двух версий |

В верхней строке есть одна кнопка **Действия**. В ней раскрываются группы «Проект», «Редактирование», «Проверить» и «Запуск». Поиска инструментов, отдельной панели групп и справки в этом меню нет. Недоступные команды объясняют причину. Меню закрывается по Escape или клику вне него.

**Помощь** — значок справа вверху рядом с уведомлениями и настройками. Он открывает только обучение, руководство, горячие клавиши и информацию о продукте. Название проекта и переход на главный экран в справке не показываются.

Над рабочим полем находится один ряд: стрелка файловой панели, выбор метода, «Алгоритм / Блоки» и три иконки раскладки (код, рядом, схема). Вкладки файлов, поиска и структуры слева тоже представлены иконками с подсказками. Поиск по файлам доступен только при выборе соответствующей вкладки; Ctrl+K сохраняет вызов палитры с клавиатуры.

На обзоре подробный путь данных и дерево вызовов раскрываются по запросу. Для начала достаточно выбрать один из трёх сценариев: разобраться, исправить проблемы или собрать метод.

## Открыть и сохранить проект

1. Нажмите **Действия → Проект → Открыть папку** или выберите пример на главной странице.
2. Разрешите браузеру доступ к выбранной папке, если он поддерживает работу с каталогами. Если используется импорт, получится редактируемая копия в памяти вкладки.
3. Посмотрите подсказку хранения внизу файловой панели. Для проекта в памяти скачайте ZIP перед закрытием вкладки. Обычное сохранение в таком проекте не создаёт постоянное облачное хранилище.
4. Откройте «Обзор», затем интересующий метод.

Исходный код остаётся обычной Java. Для серверного анализа, компиляции и выполнения он передаётся Java-сервису текущего развёртывания. Слово Web само по себе не означает наличие аккаунтов, синхронизации между устройствами или постоянного серверного диска.

## Понять метод и освободить рабочее поле

В разделе «Метод» выберите метод в подписанном списке над схемой. Рядом видны вызывающие и вызываемые методы. Нажатие на имя переходит к ним; «Назад» возвращает к предыдущему методу.

- **Алгоритм** — схема для чтения, построенная из Java. Несколько последовательных простых инструкций могут быть объединены в один блок шагов. Нажатие раскрывает их. Выбор блока подсвечивает соответствующий код.
- **Блоки** — редактор связей, который генерирует тело Java-метода. Используйте его, когда действительно хотите менять логику.
- **Иконки кода, расположения рядом и схемы** — варианты размещения редакторов; наведите курсор для подсказки.
- **Стрелка слева над полем** показывает или скрывает файловую панель. Для максимального графа выберите иконку «Только схема» и скройте файлы.

Масштаб схемы независим от масштаба страницы. «Вписать» возвращает обзор графа; длинные методы открываются в читаемом масштабе и требуют перемещения по полю.

## Блоки: входы, выходы и связи

Входы расположены **слева**, выходы **справа**. Есть два разных вида портов:

| Вид | Обозначение | Значение |
|---|---|---|
| Порядок выполнения | Стрелка | Какой блок выполняется следующим |
| Данные | Круг с подписью Java-типа | Какое значение передаётся в выражение или аргумент |

У `if` выходы `Да · true` и `Нет · false` определяют ветку. У цикла «Тело цикла» ведёт внутрь, «После цикла» продолжает метод. Порты данных различаются типом и цветом; ориентируйтесь также на подпись, поскольку один цвет недостаточен для понимания.

Основные действия:

1. **Добавить блок** открывает палитру с поиском. Она также доступна по правой кнопке мыши на поле.
2. Соедините выход со входом перетаскиванием. Порт управления соединяется с управлением, данные — с совместимым входом данных.
3. Выберите связь и нажмите Delete, чтобы удалить её. Alt+клик по порту отключает его связи. Конец провода у входа можно переподключить.
4. Выберите блок: справа появятся его Java-свойства и объяснение назначения.
5. Измените логику, проверьте полученную Java и выполните сравнение поведения. Ctrl+Z отменяет изменение графа.

Некоторые конструкции представлены сохранённым фрагментом Java вместо отдельных визуальных операций. Подпись «Java» не означает, что все внутренние шаги доступны для изменения проводами. Если у черновика не подключены обязательные входы, редактор сообщает об этом и не переносит неполную генерацию в код.

### Настройка оформления портов

1. Выберите блок в редакторе «Блоки».
2. В правой панели раскройте **Подписи входов и выходов**.
3. Для каждого порта задайте понятное название до 36 символов и цвет.
4. «Сбросить оформление» возвращает стандартные подписи и цвета.

Это оформление: Java-типы, идентификаторы портов и назначение связей не меняются. Например, порт `value: int` можно назвать «Количество товаров», но от переименования он не станет строкой. Оформление сохраняется вместе с расположением узлов в состоянии проекта текущего браузерного сеанса. Экспорт `.java` не содержит эти подписи. Полноценный перенос оформления между устройствами в этой доработке не добавлялся.

## Как работают автоматические исправления

Исправления основаны на распознавании определённых конструкций Java. Анализатор предлагает известное преобразование; он не понимает произвольный бизнес-смысл программы.

1. Откройте **Задачи → Разобрать исправление**.
2. Прочитайте причину и условия применимости. Например, частотная таблица может заменить вложенный подсчёт пар и потребовать дополнительную память.
3. Посмотрите Java до и после. Оценка Big O — структурная оценка, а не измеренный выигрыш.
4. Проверьте главный класс и перечень включённых входов. При необходимости нажмите **Настроить тестовые входы**. После изменения входов откройте предложение заново.
5. Нажмите **Применить и проверить**. Без включённых входов кнопка недоступна.
6. Текущий редактор изменится; затем выполнится сравнение с исходным снимком. Изменение не считается принятым до вашего решения.
7. При совпадении просмотрите результаты и выберите **Принять и сохранить**. При проблеме нажмите **Откатить изменение**.

Пока одно автоматическое исправление ожидает принятия или отката, следующее не применяется. Это защищает сохранённую точку отката от замены другим исправлением. Ручные изменения после исправления требуют внимания: откат возвращает затронутые файлы к сохранённому состоянию до преобразования.

Выделение класса имеет отдельный диалог: выбираются методы и имя нового класса, а исходные вызовы сохраняются через делегаты. Это ограниченное преобразование, а не автоматическое проектирование всей архитектуры.

## Что именно проверяют тесты

Основная проверка — **сравнение поведения**, а не JUnit и не тест отдельного метода.

| Что | Как используется |
|---|---|
| Исходная версия | Снимок Java при открытии проекта или последней ручной фиксации |
| Текущая версия | Содержимое редактора, включая несохранённые изменения |
| Главный класс | Java-класс с `public static void main(String[] args)`; для пакета укажите полное имя |
| Тестовый вход | Полный текст stdin для одного запуска |
| Результат | stdout, stderr и код завершения каждой версии |

Для каждого включённого входа обе версии компилируются и запускаются отдельно. stdout сравнивается побайтно. В stderr исключаются распознанные служебные строки кадров стека JVM; остальные байты участвуют в сравнении. Это означает, что основной режим не обнаруживает изменения самих исключённых stack frames. Длительность показывается для информации и не является условием совпадения.

Ожидаемый результат берётся из исходной версии. Если в обеих версиях есть одинаковая бизнес-ошибка, такой тест её не обнаружит. Для проверки бизнес-правильности нужен независимый ожидаемый результат, отдельные тесты или ручная проверка; редактор произвольного expected stdout в этой версии не добавлен.

### Настроить входы

1. Откройте **Проверка → Тестовые входы**.
2. Укажите главный класс или оставьте автоматический поиск, если точка входа одна.
3. Добавьте случай, задайте название и полный stdin. Флажок включает или исключает случай из прогона.
4. Нажмите **Проверить поведение** или F6.
5. В «Результате» раскройте каждый случай: сравните обе версии, stderr и код завершения.

Пример для учебного магазина:

```text
PRODUCT A1;Книга;BOOKS;10000;5
CUSTOMER u1;Анна;BASIC
ORDER o1;u1;A1:2
PAY o1;20000
REPORT
STATS
END
```

Это один случай целиком. `PRODUCT`, `ORDER` и остальные команды нужны именно этому примеру. Для другой программы используйте её формат ввода.

Хороший набор охватывает обычный путь, пустой ввод, минимальные и максимальные допустимые значения, повторяющиеся значения, отсутствие искомого элемента и ошибки формата. Число случаев само по себе не показывает их силу.

### Сохранить набор

«Экспорт JSON» скачивает `blueprints-tests.json`. Положите его в корень проекта, чтобы загрузить набор при следующем открытии:

```json
{
  "mainClass": "Main",
  "cases": [
    { "name": "Обычный случай", "input": "3\n1 2 3\n", "enabled": true },
    { "name": "Пустой ввод", "input": "", "enabled": true }
  ]
}
```

Файл должен соответствовать протоколу вашей программы. Сам по себе экспорт скачивает файл, но не записывает его в выбранную папку. Изменение main или входов делает предыдущий отчёт устаревшим.

### Как читать итог

| Состояние | Что делать |
|---|---|
| Совпало на выбранных входах | Просмотреть случаи, затем принять изменение |
| Поведение изменилось | Открыть случай с расхождением, изучить diff, исправить или откатить |
| Сборка не прошла | Прочитать диагностику javac: сравнение выполнения не завершилось успешно |
| Ошибка среды запуска | Проверить доступность Java-сервиса/runner; это не доказательство регрессии программы |
| Устарело | Перезапустить: после прогона изменились код, главный класс или входы |

Совпадение на конечном наборе входов не гарантирует эквивалентность на всех данных. Не заменяйте исходную версию только ради зелёного результата: **Считать текущую исходной** действительно заменяет точку сравнения и теперь требует подтверждения.

## Дополнительные эксперименты

Они собраны в раскрываемом блоке **Расширенные эксперименты**.

- **Качество тестов.** Для выбранного метода выполняется до шести небольших мутаций и используются первые пять включённых входов. Если мутация выжила, входы могут не задевать этот путь; возможна также эквивалентная мутация. Это подсказка для усиления тестов.
- **Скорость.** Сравнивает поддерживаемый числовой метод на заданных размерах, с повторениями. Область применимости ограничена: это не универсальный benchmark любого Java-приложения.
- **Минимальный вход.** Уменьшает числовой вход формата `n` и `n` целых, сохраняя найденное расхождение. Протокол команд магазина этим инструментом не поддерживается.
- **Генератор входов.** Создаёт числовые наборы заданной формы с воспроизводимым seed. Он не угадывает команды вашей программы и не создаёт автоматически корректный магазинный сценарий.

## Если что-то не работает

| Симптом | Проверка |
|---|---|
| Команда недоступна | Прочитайте причину под ней: открыт ли проект, Java-файл, выбран ли метод |
| Нет схемы | Посмотрите ошибки синтаксиса и доступность Java-сервиса |
| Нет результатов F6 | Включён ли хотя бы один stdin, правильно ли выбран главный класс |
| Запуск ждёт или завершён по лимиту | Достаточно ли входных данных, не ждёт ли Scanner продолжения |
| Изменение не применяется | Не устарел ли исходник и завершено ли предыдущее ожидающее исправление |
| Пропали данные после обновления вкладки | Был ли проект только в памяти и скачан ли ZIP |
| Непонятно сообщение | Откройте колокольчик: сообщения собраны с временем в одном списке |

Для знакомства пройдите один полный цикл на примере: обзор → `countRepeatedQuantities` → предложение частотного индекса → просмотр diff → проверка на шести входах → просмотр результатов → откат или сохранение. Затем перенесите эту последовательность на свой проект.


В рабочем поле нет постоянной легенды, повторного названия метода и списков «Вызывает / Вызывают». Обозначения цветов, типов портов и различие управления и данных описаны в этом руководстве и доступны только при открытии помощи.
