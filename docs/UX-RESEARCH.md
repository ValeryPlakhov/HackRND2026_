# Основания для доработки Web UX

Дата исследования: 25.10.2026. База реализации: `fcf2330` после v5.0.0. Это инженерный разбор и проверка сценариев, а не исследование с внешними пользователями; измеренного роста удобства или скорости пока нет.

Рекомендации адаптированы к задачам Java-редактора. Расположение и визуальный стиль сторонних продуктов не копировались буквально. В отличие от потоков Node-RED, граф Java отдельно передаёт управление и значения, поэтому подписи и формы этих портов различаются.

## Исправленные причины поломок

1. В `IdeApplication.start()` отсутствовала подписка `DocumentStore.changed`: оставшаяся стрелочная функция не выполняла обработку. Восстановлена связь событий документов с актуальностью отчёта, состоянием сохранения и перерисовкой.
2. `QualityLab.renderPanel()` по умолчанию рисовал в скрытый `ide-panel-body`, когда пользователь находился на странице проверки. Выбор вкладки теперь обновляет видимый `ws-verify-panel`.
3. Открытие тестов из разных разделов вело в разные места. Основная проверка маршрутизируется на единый экран; прогресс задания обновляется там же.
4. Команда исправления из задачи могла сразу менять код. Теперь она открывает объяснение, diff и список включённых входов. Нет входов — нет применения; второе исправление блокируется до решения по первому.
5. Ошибка инфраструктуры в подробном результате выглядела как изменение поведения. Добавлено явное состояние «Не удалось проверить: ошибка среды запуска».

## Что проверить с пользователями

- Новый пользователь без подсказок находит свой main, открывает метод и объясняет разницу между портами данных и управления.
- Находит тестовые входы, добавляет граничный случай и объясняет, что выступает ожидаемым результатом.
- До применения может сказать, какой Java-код поменяется и чем подтвердится результат.
- Отличает совпадение на входах, устаревший результат, ошибку сборки и отказ среды.
- Возвращается из режима фокуса и повторно запускает обучение.

Следующий цикл стоит провести на реальных задачах незнакомого монолита и нескольких размерах экранов, фиксируя ошибки и время выполнения, а не только мнение о внешнем виде.
