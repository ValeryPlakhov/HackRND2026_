# Автоматическая проверка

Одна команда собирает движок и прогоняет все наборы:

```powershell
python tests/verify.py
```

Нужны JDK 21+, Node 22+ и Python 3.11+. Скрипт компилирует `src/`, запускает unit-тесты интерфейса, поднимает движок на `localhost:18080` в режиме локального запуска и прогоняет интеграционные наборы против настоящего `javac` и отдельных JVM. Потом считает строки исходников. Итог записывается в [verification-summary.json](verification-summary.json), журналы — в `docs/*.log`.

## Наборы

| Набор | Файл | Что проверяет |
|---|---|---|
| Unit | `tests/unit/*.test.mjs` | Модель документа и редактор, команды и горячие клавиши, раскладка графа, лексер, diff на 300 случайных последовательностях правок, ZIP и экспорт, открытие и запись папки в браузере (подставной каталог), режимы и меню «Инструменты», проверка, что у каждой кнопки есть обработчик |
| API движка | `tests/test_api.py` | Разбор и UTF-16 позиции, scope Java на примере, правки блоков (замена, вставка, удаление), оптимизация монолита на 1000 строк, сравнение байтов вывода, лимиты вывода и времени, отказ от небезопасных путей, CORS |
| Анализ и лаборатории | `tests/test_studio_api.py` | Анализ проекта и граф вызовов, каталог правил, сложность и данные, планы с хешами, устаревшие и пересекающиеся планы, генератор входов, мутации, бенчмарк, уменьшение контрпримера, задания и отмена, SARIF, манифест проверки |
| IDE | `tests/test_ide_api.py` | Проекты с пакетами и выбор main-класса, анализ и планы на монолите магазина, декомпозиция с проверкой поведения, объяснение пропущенных методов, стек-трейсы при сдвиге строк, правила поиска в коллекциях и их исправления, все встроенные примеры проходят свои тесты |
| Блупринт: круговой тест | `tests/blueprint_roundtrip.mjs` | Каждый метод всех примеров импортируется в блок-граф (`/api/blueprint`), Java генерируется обратно, и поведение совпадает с исходным. Отдельные пробы: двойной минус, тернарный получатель вызова, смесь унарных операторов, комментарии |
| Регрессии аудита | `tests/test_audit_regressions.py`, `tests/unit/audit.test.mjs` | Контрпримеры независимого аудита (F01, F02, F05–F12, F18, F19): stderr и main, безопасность `contains-to-set` и `dedupe-set`, свежие имена, привязка имён при декомпозиции, генерация выражений, типы пинов, устаревание результата. Подробности в [AUDIT-RESPONSE.md](AUDIT-RESPONSE.md) |

## Что считается проверкой поведения

Для каждого входа эталон и новая версия компилируются отдельно и запускаются в отдельных JVM. Вход совпал, если совпали байты stdout, байты stderr без строк кадров стека JVM (`	at …(File.java:N)`, `... N more`) и код завершения, обе версии действительно запустились, а ни одна не упёрлась в таймаут или лимит вывода. Если запуск сорвался по причине инфраструктуры, результат «не определено» и не засчитывается как пройденный. Указанный, но не найденный main-класс — ошибка, а не подмена первым найденным. Если не собралась хотя бы одна версия, проверка не пройдена. Пустой набор входов отклоняется.

Совпадение на конечном наборе — свидетельство, а не доказательство эквивалентности. Насколько хорошо набор ловит изменения, показывает мутационное тестирование.

## Встроенные примеры

| Пример | Строк | Входов | Что демонстрирует |
|---|---:|---:|---|
| `shop-monolith` | 878 | 6 | Реалистичный монолит: коллекции, исключения, команды из stdin, 6 планов оптимизации, декомпозиция |
| `large-monolith` | 1052 | 8 | 51 метод, O(n²) подсчёт пар, массовая декомпозиция вычислений |
| `language-showcase` | 81 | 4 | Обязательный и бонусный Java scope в одном файле |
| `pair-analyzer`, `text-pipeline` | малые | 3 | Учебные случаи для O(n²) и накопления строки |

Входы лежат в `blueprints-tests.json` каждого примера. IDE загружает их автоматически при открытии папки.
