# Автоматическая проверка

Одна команда собирает движок и прогоняет все наборы:

```powershell
python tests/verify.py
```

Нужны JDK 21+, Node 22+ и Python 3.11+. Скрипт компилирует `src/`, запускает unit-тесты интерфейса, поднимает движок на `localhost:18080` в режиме локального запуска и прогоняет интеграционные наборы против настоящего `javac` и отдельных JVM. Потом считает строки исходников и, если собран runtime настольной версии, проверяет запуск проектов встроенной Java. Итог записывается в [verification-summary.json](verification-summary.json), журналы — в `docs/*.log`.

## Наборы

| Набор | Файл | Что проверяет |
|---|---|---|
| Unit | `tests/unit/*.test.mjs` | Модель документа и редактор, команды и горячие клавиши, раскладка графа, лексер, diff на 300 случайных последовательностях правок, ZIP и экспорт, контракты настольной оболочки |
| API движка | `tests/test_api.py` | Разбор и UTF-16 позиции, scope Java на примере, правки блоков (замена, вставка, удаление), оптимизация монолита на 1000 строк, сравнение байтов вывода, лимиты вывода и времени, отказ от небезопасных путей, CORS |
| Анализ и лаборатории | `tests/test_studio_api.py` | Анализ проекта и граф вызовов, каталог правил, сложность и данные, планы с хешами, устаревшие и пересекающиеся планы, генератор входов, мутации, бенчмарк, уменьшение контрпримера, задания и отмена, SARIF, манифест доказательств |
| IDE | `tests/test_ide_api.py` | Проекты с пакетами и выбор main-класса, анализ и планы на монолите магазина, декомпозиция с проверкой поведения, объяснение пропущенных методов, стек-трейсы при сдвиге строк, правила поиска в коллекциях и их исправления, все встроенные примеры проходят свои тесты |
| Настольный runtime | `tests/desktop-runtime.mjs` | Встроенная Java собирает и запускает многофайловый проект в пути с кириллицей, диагностика компилятора, выбор main, stdin в UTF-8, лимит вывода, отмена, таймаут |
| Запуск EXE | `tests/test_desktop_smoke.py portable` / `single-exe` | Настоящее окно Electron стартует, поднимает движок, загружает IDE и выполняет экспорт |
| Сценарий в EXE | `tests/test_desktop_smoke.py portable --scenario` / `single-exe --scenario` | Собранное приложение в скрытом окне проходит путь кейса через настоящий IPC: копирует пример, фиксирует эталон, анализирует проект, применяет оптимизацию, выделяет класс в новый файл, после каждого шага проверяет поведение и сохраняет файлы на диск |

## Что считается проверкой поведения

Для каждого входа эталон и новая версия компилируются отдельно и запускаются в отдельных JVM. Вход совпал, если совпали байты stdout, stderr без строк стека `at …` и код завершения, а ни одна версия не упёрлась в таймаут или лимит вывода. Если не собралась хотя бы одна версия, проверка не пройдена. Пустой набор входов отклоняется.

Совпадение на конечном наборе — свидетельство, а не доказательство эквивалентности. Насколько хорошо набор ловит изменения, показывает мутационное тестирование.

## Встроенные примеры

| Пример | Строк | Входов | Что демонстрирует |
|---|---:|---:|---|
| `shop-monolith` | 878 | 6 | Реалистичный монолит: коллекции, исключения, команды из stdin, 6 планов оптимизации, декомпозиция |
| `large-monolith` | 1052 | 8 | 51 метод, O(n²) подсчёт пар, массовая декомпозиция вычислений |
| `language-showcase` | 81 | 4 | Обязательный и бонусный Java scope в одном файле |
| `pair-analyzer`, `text-pipeline` | малые | 3 | Учебные случаи для O(n²) и накопления строки |

Входы лежат в `blueprints-tests.json` каждого примера. IDE загружает их автоматически при открытии папки.
