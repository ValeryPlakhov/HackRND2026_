# Продукт: для кого и как пользоваться

Blueprints IDE помогает разобраться в чужом Java-монолите и менять его, не ломая поведение. Версия 4.3 перестроена вокруг задач пользователя. Раньше IDE открывала проект сразу в блок-схеме метода `main`, и было непонятно, с чего начать. Теперь работа разделена на четыре режима по задачам.

## Кто пользуется и зачем

| Пользователь | Задача | Режим |
|---|---|---|
| Разработчик на сопровождении монолита | Найти, где проблема, исправить и убедиться, что ничего не сломал | Задачи → Проверка |
| Новый сотрудник | Понять программу: где вход, как идут данные, что вызывает что | Обзор → Метод |
| Техлид | Оценить риск изменения, решить, что выносить из монолита | Обзор, Задачи (раздел «Разделить монолит») |
| Студент или автор новой логики | Собрать метод из блоков и сразу получить Java | Метод → «Правка блоками» |

## Четыре режима

Переключатель режимов находится в верхней панели, горячие клавиши Alt+1…4. Alt+← возвращает на предыдущий метод.

**Обзор — что это за программа.** Открывается первым после загрузки проекта.
- Паспорт проекта: размер, точка входа, число рисков, число исправлений, которые IDE сделает сама, состояние проверки.
- Путь данных: методы, сгруппированные по ответственности (ввод → проверки → вычисления → вывод). Служебные методы скрыты.
- Дерево вызовов от `main`: разбор команд виден сразу, ветки раскрываются.
- «С чего начать»: пять самых рискованных методов с причиной, например «сложность O(n²), 11 ветвлений».
- Три сценария: разобраться в коде, исправить проблемы, собрать метод из блоков.

**Метод — логика одного метода.**
- Над схемой — контекст: кто вызывает метод, что вызывает он сам, сложность, риски. Клик по вызову переходит к нему, кнопка «Назад» возвращает.
- «Чтение» показывает схему алгоритма: циклы, условия, выходы. Подряд идущие простые операторы свёрнуты в один блок «N шагов». Метод на 31 оператор превращается в схему из 15 узлов. Узлы с замечаниями анализа помечены. Клик по узлу переводит курсор кода на нужную строку.
- «Правка блоками» включает редактор с пинами и проводами. Каждая правка сразу генерирует Java.

**Задачи — что сделать с кодом, по приоритету.**
- Риски отсортированы по риску метода. Если у риска есть автоисправление, которое устраняет именно его (например, индекс частот вместо вложенного цикла), кнопка «Исправить и проверить» стоит прямо в карточке риска. Исправление, которое лишь лежит в том же методе, к риску не привязывается.
- Ускорения и упрощения, которые IDE сделает сама: показывают изменение и оценку Big O до и после.
- «Разделить монолит»: группы методов, которые можно вынести в отдельный класс с делегатами.
- Советы по стилю свёрнуты, чтобы не заслонять риски.
- После применения изменения сверху появляется результат проверки с двумя кнопками: «Принять и сохранить» и «Откатить». Изменение остаётся незавершённым, пока пользователь не выберет одно из двух.

**Проверка — ничего не сломалось?** Четыре шага в одну строку: эталон → ваши изменения (какие файлы) → тестовые входы → результат. Ниже — входы, результаты по каждому входу, сила тестов (мутации), скорость, уменьшение контрпримера. Ошибка среды запуска показывается как «не определено», а не как регрессия.

## На что ориентировались

| Аналог | Что взяли | Чем отличаемся |
|---|---|---|
| Sourcetrail, Call Hierarchy в IntelliJ | Дерево вызовов, навигация вызывающий ↔ вызываемый, синхронизация схемы и кода | Схема метода строится по AST javac и сразу показывает риски |
| CodeScene, SonarQube | Hotspots: приоритет по риску, а не длинный список замечаний | Исправление запускается из карточки риска и сразу проверяется запуском |
| OpenRewrite, рефакторинги IDE | Автоматическое преобразование с предпросмотром diff | После применения — дифференциальный запуск эталона и новой версии и откат одной кнопкой |
| Code2Flow, Visustin | Схема алгоритма из кода для чтения | Схема сжата до структуры: циклы, ветвления, выходы |
| Blueprints в Unreal Engine | Визуальное программирование блоками с пинами и проводами | Свой визуальный язык; блоки генерируют обычную Java, а код остаётся источником истины |

## Что не обещаем

- Ответственности и риск — эвристики по признакам в коде. Это ориентир для чтения, а не оценка качества.
- Совпадение поведения на тестовых входах — свидетельство, а не доказательство эквивалентности для всех данных.
- Экономия времени не измерялась. Проверять её нужно пилотом: одинаковые задачи на незнакомом монолите («найти точку входа», «проследить ввод → правило → вывод», «назвать затронутых вызывающих») в обычной IDE и в Blueprints, с замером времени и числа ошибок.
