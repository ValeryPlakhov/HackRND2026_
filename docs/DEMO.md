# Настольная IDE 3 · показ за 3 минуты

1. Двойной клик Blueprints-IDE-3.exe. Нажать «Открыть папку» и выбрать Java-проект.
2. Открыть файл, выбрать метод, нажать блок. Показать объяснение и переход к строке.
3. Изменить условие через блок, сохранить Ctrl+S и запустить F5. Показать настоящий вывод JVM.
4. Открыть историю файла и diff; восстановить старый код в редактор.
5. Показать поиск по проекту и переключатель языков: Java доступна, остальные Coming soon.

Технические вопросы: DESKTOP.md. Проверки: 272 теста плюс запуск реального EXE. Границы: Windows x64; Maven/Gradle читаются, зависимости автоматически не загружаются; локальный запуск доверенного кода не sandbox.

# Защита через пользовательскую задачу

## Первые три минуты — без Java

1. Открыть главную. «Мы хотим, чтобы человек выразил логику задачи через понятные действия, а синтаксис взял на себя инструмент».
2. Готовые примеры → Скидка в магазине. Показать вопрос «Сумма покупки», условие и два пути «Да / Нет».
3. Нажать условие, изменить порог и сохранить. Ни одной строки Java не вводится.
4. Запустить на суммах ниже и выше порога. Показать реальный результат и подпись «Выполнено на Java».
5. Через плюс добавить «Показать» на нужный путь. Изменить сообщение и повторить запуск.
6. Стоимость покупок: список цен, число «Итого», повтор и накопление. Показать пустой список и несколько цен.
7. «Как получился ответ?» подсвечивает шаги визуальной модели. Это объяснение логики, не JVM debugger.
8. Сохранить проект: JSON-схема, обычная Main.java, инструкция. Схему можно снова открыть. Java по отдельной кнопке, она не нужна для начала работы.

## Затем инженерная проверка

Расширенная Studio открывается отдельно на expert.html. Монолит 1052 строки / 51 метод, AST-граф и исходник. План histogram с source hash, apply → 8/8 differential gate, benchmark с честными малыми/большими входами, mutation, reducer и evidence ZIP. Подробная инструкция README-EXPERT.md.

205 тестов проверяют обе части: 141 unit + 22 базовых API + 36 Studio API + 6 Builder API. Внутри Builder API выполняются сгенерированные из блоков программы и сравниваются с моделью. Число subcases не прибавляется к числу test cases. Source audit исключает deps, generated examples, JSON и docs.

## Вопросы

| Вопрос | Ответ |
|---|---|
| Пользователь должен знать Java? | В конструкторе достаточно блоков и обычных полей; Java создаётся автоматически. |
| Это только нарисованная схема? | Из неё генерируется Main.java, которая компилируется и выполняется отдельной JVM. |
| Любой Java можно редактировать блоками? | Конструктор имеет свой ограниченный структурный язык. Анализ существующей Java — в отдельной Studio. |
| Магазин реально подключён? | Нет, это понятный пример условия, а не интеграция с заказами. |
| Что без backend? | Явно подписанный браузерный предпросмотр модели, без заявления о выполнении Java. |
| Всем точно понятно? | Интерфейс упрощён; пользовательское исследование с аудиторией ещё не проводилось. |
| Код изолирован? | Trusted local не sandbox; Docker здесь не проверен. |
