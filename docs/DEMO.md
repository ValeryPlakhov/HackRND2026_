# Сценарий демонстрации

Полный путь кейса на одном примере, около пяти минут. Нужны только `BlueprintsIDE.exe` и встроенный пример.

## 1. Обзор: что это за программа (40 секунд)

1. Запустить `BlueprintsIDE.exe` → **Открыть пример монолита**. Откроется режим **Обзор**.
2. Паспорт: 878 строк, 13 классов, 79 методов, точка входа `ShopMonolith.main`, 5 рисков, исправления, которые IDE сделает сама, 6 тестовых входов. IDE уже зафиксировала эталон.
3. Путь данных: ввод → проверки → вычисления → вывод. Дерево вызовов: `main → execute →` 11 команд магазина. Сказать: «Новый человек за минуту видит, как устроена программа».

## 2. Метод: как это работает (50 секунд)

1. «Разобраться в коде» → режим **Метод**, `main`: слева код, справа схема шагов. Простые операторы свёрнуты, видны цикл, условия и выходы.
2. Над схемой кликнуть `execute()` → переход к разбору команд. Alt+← или «Назад» — возврат.
3. Клик по узлу схемы переводит курсор кода на эту строку.
4. «Правка блоками» → блоки с пинами. **Новый метод** → `int add(int a, int b)`, Get `a`, Get `b`, ПКМ → «a + b», провода в Return: в коде появится `return a + b;`.

## 3. Задачи: что исправить (40 секунд)

1. Режим **Задачи**. Сверху риски по приоритету, внизу свёрнутые советы по стилю: они не заслоняют важное.
2. Риск «Вложенные циклы: O(n²)» в `countRepeatedQuantities`. В карточке — «Индекс частот вместо парного обхода, O(n²) → O(n)». «Изменение» показывает diff.
3. Сказать: «К риску привязано только исправление, которое устраняет именно его».

## 4. Исправить и проверить (40 секунд)

1. **Исправить и проверить**. Код меняется, запускаются эталон и новая версия: «поведение совпало 6/6».
2. В баннере две кнопки: «Принять и сохранить» и «Откатить». Показать «Откатить», затем применить снова и принять.

## 5. Декомпозиция (60 секунд)

1. **Задачи → Разделить монолит**: группы «Вывод», «Вычисления», «Проверки» с предлагаемыми классами.
2. **Выделить класс и проверить** у вывода. В окне видны отмеченные методы; метод `main` недоступен, потому что точка входа остаётся на месте.
3. **Выделить и проверить**: появится `ShopReports.java`, в монолите останутся делегаты, проверка снова 6/6.
4. Сказать: «Перенос проверяется дважды: сначала javac собирает проект, затем тесты сравнивают поведение».

## 6. Сломать и поймать (40 секунд)

1. В `bestDiscount` или `TierDiscount` изменить блок (двойной клик по блоку), например `subtotal * 10 / 100` → `subtotal * 15 / 100`.
2. Режим **Проверка** → «Проверить поведение» (F6). Шаги вверху: эталон → ваши изменения → входы → «Расхождение». Проверка покажет расхождение: входы, где скидка влияет на сумму, красные, ниже diff stdout эталона и новой версии.
3. Ctrl+Z в редакторе кода, затем F6 — снова зелёный.

## 7. Отчёт (20 секунд)

**Отчёт** в панели проверки сохраняет ZIP: эталон, новая версия, входы, результаты с хешами, patch, анализ и HTML-отчёт для печати.

## Ответы на вопросы

| Вопрос | Ответ |
|---|---|
| Это настоящая Java? | Да. Разбор — `javac`, сборка — `javac --release 21`, запуск — отдельные JVM. Свой интерпретатор не используется |
| Синхронизация в обе стороны? | Код → граф: разбор после паузы при наборе. Граф → код: изменить, добавить до или после, удалить блок; правка проверяется парсером |
| Что если чужой монолит? | Открывается любая папка с Java (пакеты, до 300 файлов). Входы задаются в панели «Проверка поведения», генерируются по seed или берутся из `blueprints-tests.json` |
| Почему stderr сравнивается без номеров строк? | После рефакторинга строки законно сдвигаются в стек-трейсе. Тип и текст исключения по-прежнему сравниваются (тест `test_10`) |
| Доказана ли эквивалентность? | Нет: это сравнение на конечном наборе входов. Силу набора показывает мутационное тестирование во вкладке «Сила тестов» |
| Big O точный? | Это структурная оценка по AST с явными допущениями. Вызовы других методов и рекурсия отдельно не доказываются |
| Нужен интернет или JDK? | Нет. Java 21 внутри EXE, всё работает локально |
