# Сценарий демонстрации

Полный путь кейса на одном примере, около пяти минут. Нужны только `BlueprintsIDE.exe` и встроенный пример.

## 1. Монолит (30 секунд)

1. Запустить `BlueprintsIDE.exe` → **Открыть пример монолита**.
2. Откроется `ShopMonolith.java`: 878 строк, склад, клиенты, заказы, скидки, возвраты и отчёты в одном файле. В нижней строке появится «Поведение не проверено»: IDE уже зафиксировала эталон.
3. Сказать: «Код читается javac, это настоящая Java, а не упрощённая модель».

## 2. Граф (40 секунд)

1. Справа блупринт `main` в стиле Unreal: белые exec-провода задают порядок, цветные провода несут значения.
2. Кликнуть переменную `line` в панели слева — подсветятся все узлы, которые её читают и пишут.
3. **Новый метод** → `int add(int a, int b)`. Get `a`, Get `b`, ПКМ → «a + b», провода в Return: в коде появится `return a + b;`.
4. Перетащить провод с одного входа на другой, Alt+клик по пину — связь рвётся, код обновляется сразу.

## 3. Диагноз (60 секунд)

1. Панель **Анализ** (иконка мишени, Ctrl+Shift+A): 79 методов, найденные риски и советы.
2. Кликнуть «Вложенные циклы: O(n²)» → откроется `countRepeatedQuantities`, строка 712. Узел помечен на схеме, в заголовке видны `O(n^2)` и CC.
3. Раскрыть «Почему O(n^2)»: оценка опирается на конкретные строки и перечисляет допущения.
4. Показать находку «Линейный поиск в коллекции внутри цикла» в `countDistinctBuyers`: значок ✦ означает, что есть автоматическое улучшение.

## 4. Улучшение (60 секунд)

1. В инспекторе узла нажать **Показать улучшение**, откроется панель **Улучшения**.
2. «Индекс частот вместо парного обхода» → **Посмотреть изменение**: diff, O(n²) → O(n), условия применимости.
3. **Применить и проверить**. Код меняется в редакторе, и сразу запускается проверка: «Поведение сохранено 6/6».
4. Так же применить «Проверка уникальности через HashSet» для `countDistinctBuyers`.

## 5. Декомпозиция (60 секунд)

1. **Анализ → Декомпозиция**: группы «Вывод результата», «Вычисления», «Проверки».
2. **Выделить** у «Вывод результата». В окне видны отмеченные методы; метод `main` недоступен, потому что точка входа остаётся на месте.
3. **Выделить и проверить**: появится `ShopReports.java`, в монолите останутся делегаты, проверка снова 6/6.
4. Сказать: «Перенос проверяется дважды: сначала javac собирает проект, затем тесты сравнивают поведение».

## 6. Сломать и поймать (40 секунд)

1. В `bestDiscount` или `TierDiscount` изменить блок (двойной клик по блоку), например `subtotal * 10 / 100` → `subtotal * 15 / 100`.
2. **F6**. Проверка покажет расхождение: входы, где скидка влияет на сумму, красные, ниже diff stdout эталона и новой версии.
3. Ctrl+Z в редакторе кода, затем F6 — снова зелёный.

## 7. Доказательства (20 секунд)

**Отчёт** в панели проверки сохраняет ZIP: эталон, новая версия, входы, результаты с хешами, patch, анализ и HTML-отчёт для печати.

## Ответы на вопросы

| Вопрос | Ответ |
|---|---|
| Это настоящая Java? | Да. Разбор — `javac`, сборка — `javac --release 21`, запуск — отдельные JVM. Свой интерпретатор не используется |
| Синхронизация в обе стороны? | Код → граф: разбор после паузы при наборе. Граф → код: изменить, добавить до или после, удалить блок; правка проверяется парсером |
| Что если чужой монолит? | Открывается любая папка с Java (пакеты, до 300 файлов). Входы задаются в панели «Проверка поведения», генерируются по seed или берутся из `blueprints-tests.json` |
| Почему stderr сравнивается без номеров строк? | После рефакторинга строки законно сдвигаются в стек-трейсе. Тип и текст исключения по-прежнему сравниваются (тест `test_10`) |
| Доказана ли эквивалентность? | Нет: это сравнение на конечном наборе входов. Силу набора показывает мутационное тестирование во вкладке «Сила тестов» |
| Big O точный? | Это структурная оценка по AST с явными допущениями. Вызовы других методов и рекурсия отдельно не доказываются |
| Нужен интернет или JDK? | Нет. Java 21 внутри EXE, всё работает локально |
